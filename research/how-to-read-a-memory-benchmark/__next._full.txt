38:T1062,<p>&quot;It remembers you&quot; is a sentence any AI product can print. A score is harder to print, which is why memory systems now quote benchmark numbers. The numbers are useful. They are also easy to misread.</p>
<p>This is a short guide to what the common tests measure, what they do not, and what to ask before you believe a number. That includes ours.</p>
<h2>What the tests are</h2>
<p>A memory benchmark gives a system a long history of conversation, then asks questions that can only be answered from that history.</p>
<p><strong>LoCoMo</strong> is one of the first widely used ones. Its conversations are long on purpose: about 300 turns and 9,000 tokens each on average, spread over as many as 35 sessions. It asks questions about them, and also tests summarising events (<a href="https://arxiv.org/abs/2402.17753" rel="noopener noreferrer">Maharana and others, 2024</a>).</p>
<p><strong>LongMemEval</strong> has 500 questions and sorts them by the ability each one needs: pulling out a fact, reasoning across several sessions, reasoning about time, noticing that a fact has changed, and knowing when to say &quot;I was never told that&quot;. Its authors found that commercial chat assistants and long-context models lost about 30% accuracy when they had to hold information across sustained use (<a href="https://arxiv.org/abs/2410.10813" rel="noopener noreferrer">Wu and others, ICLR 2025</a>).</p>
<p><strong>Leaderboards</strong> put several tests together. The <a href="https://agent-memory-leaderboard-leaderboard.static.hf.space/index.html" rel="noopener noreferrer">Agent Memory Leaderboard</a>, for example, runs six text benchmarks and reports seven kinds of ability, among them plain fact recall, reasoning about time and events, and two that most single tests skip: how a system governs its memory, and how it handles privacy.</p>
<h2>What a score does not tell you</h2>
<p><strong>Which model answered.</strong> A memory system finds the right lines. A language model then writes the answer from them. Swap that model for a stronger one and the score rises, though the memory has not changed. Two scores are only comparable if the same model answered and the same model marked.</p>
<p><strong>How much was fetched.</strong> A system that hands the model fifty lines will often beat one that hands it five. It will also cost more on every question, and it will be slower. A score with no cost beside it is half a result.</p>
<p><strong>Whether the system was tuned on the test.</strong> If the people who built it adjusted it while looking at the test&#39;s own questions, the number says how well it knows the test, not how well it will know your users.</p>
<p><strong>Whether it can forget.</strong> Most tests reward a system for holding on to everything. Real users say &quot;forget that&quot;. A system that cannot do so cleanly is a problem no recall score will show you.</p>
<p><strong>Whether your users talk like the test.</strong> Benchmark conversations are tidy English. Yours may be short, mixed-language and full of names. The only test that settles it is your own data.</p>
<h2>Five questions for any memory vendor</h2>
<ol>
<li>Which benchmark, and which version of it?</li>
<li>Which model wrote the answers, and which model marked them?</li>
<li>Was the system adjusted using the test&#39;s own questions?</li>
<li>What happens, step by step, when a user says &quot;forget that&quot;?</li>
<li>What does one stored conversation cost, what does one search cost, and how long does a search take?</li>
</ol>
<p>A vendor who answers all five plainly is worth a trial. One who answers with a bigger number is not.</p>
<h2>Where we stand</h2>
<p>Nenai, our memory engine, is entered in the Agent Memory Leaderboard. Its review is not published yet, so we are not quoting a score here. When it is, we will link the result from the <a href="/anita-claude-v1/nenai/">Nenai page</a>, with the model that answered beside it.</p>
<p>We work to one rule when we measure ourselves: we test on a copy we build from the public data, and we do not tune on the questions a benchmark holds back.</p>
<p>And the five questions above are the ones we expect to be asked.</p>
